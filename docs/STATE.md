Flow: idea, then ready after the owner's go-ahead, doing, then waiting-owner if an owner check remains, closed when done. - **Working rules to keep AI usage down (owner asked, 10 Nov):** (1) keep code pull requests few and small (the strict up-to-date rule is off, see "Branch protection", so a merge no longer forces an update-branch and CI re-run on the others); (2) routine bot events (Cloudflare previews, screens, perf-ab comments, check suites for an old head) get no action and no long reply; (3) never poll or sleep-and-check: wait for the PR or check-suite event and read it once; a workflow run with no PR sends no event, so schedule one `send_later` check-in and read it once; (4) before re-running a red check, see whether main fails the same test, and re-run at most once; (5) read only `docs/STATE.md`, the one doc for the task and the files to change, and query data with a one-line script; (6) the platform unsubscribes a session from a pull request when it merges, so only unsubscribe by hand from one that is closed unmerged or abandoned; (7) keep final replies to a sentence or two.
- **Branch protection (owner, 10 Nov):** `main` requires the `gate` check but no longer requires branches to be up to date ("strict" is off; verified by `gh api repos/<repo>/branches/main/protection`). Reason: every merge made every other open pull request "behind" and cost an update-branch plus a ~25 minute CI re-run (the #563 race); no merge queue exists for a personal repository (#593). Consequence for merging: merge a green pull request without updating its branch first; after each merge read the `checks` and `deploy` runs on main for that commit, because a pull request is now tested on the main it branched from, not on the latest main. Update a branch by hand only when two open pull requests touch the same file or the same behaviour (then test both together), and when main goes red after a merge, fix or revert first, before any other merge. If this causes red mains, the fallback is the data train (data jobs open pull requests against a staging branch that lands on main once a day). Only the owner changes this setting; sessions cannot (the proxy refuses it).
